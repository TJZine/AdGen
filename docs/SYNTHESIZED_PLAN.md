# Synthesized Project Plan: AdGen Template-to-Flyer Generator

This document consolidates and synthesizes the findings and specifications generated by the five specialized review subagents (Product/UX, Architecture/Data Model, Layout Engine/Renderer, Export/AI Handoff, and QA/Production Readiness). It serves as the authoritative blueprint for the AdGen project implementation.

---

## 1. Decisions Accepted & Integrated

The following core architectural, layout, and workflow decisions proposed by the subagents are accepted into the project specification:

### A. Core Workflow & UX Decisions

1. **Constraint-First Compiler First, Editor Second**: The application will enforce a structured workflow where layout coordinates are calculated mathematically. Drag-and-drop coordinates will be bound strictly to grid elements, section order, and priority shifts, eliminating freeform graphic drawing layers.
2. **AI Polish + Exact Overlay Process**: To bypass AI text corruption (hallucinated letters/swirls), the workflow will export text-free layout skeletons (`rough-layout-background-only.png`) to AI tools, then re-apply precise vector-sharp overlays on top of the imported polished background.
3. **Dual-Mode Workspace UI**:
   - **Mode A (Content Table)**: Spreadsheet-like grid for inputting items, sections, and values, supporting drag-and-drop row reordering.
   - **Mode B (Layout Canvas)**: Visual canvas preview with properties inspector (focal crops, priority toggles, and density slider) and a layout variant picker.

### B. Architecture & Data Model Decisions

4. **Zod Validation & Zod Tolerant Parsing**: All domain models will be enforced using Zod schemas. Legacy schemas or missing properties during version upgrades will be handled using Zod `.default()` and `.catch()` catchalls to prevent UI crashes.
5. **Sequential JSON Migration Pipeline**: A migrations script (`src/lib/schemas/migrations.ts`) will run sequential updates on imported project files based on their `schemaVersion` tag.
6. **SQLite Hybrid Storage (JSON serialization)**: Instead of mapping volatile layout coordinates and item models to individual SQLite relational tables, the SQLite database (managed via Prisma ORM) will store sections, items, styles, and positions serialized as a single `contentJson` string. Project search metadata (e.g. project name, type) will remain queryable columns.

### C. Layout Engine & Renderer Decisions

7. **Hierarchical Grid Partitioning (HGP)**: The layout engine will be built as a pure, browser-independent TypeScript module (`lib/layout/solver.ts`). It will vertically partition the canvas into Header, Footer, and Main content zones, budget section heights based on priority weights, and arrange grid cells based on density configuration.
8. **Iterative Text Fitting & Ellipses Fallback**: A character-width heuristic table (`lib/layout/textFit.ts`) will estimate word wrapping and scale fonts down incrementally (down to a limit of 10px / 8pt) before enforcing text truncation and flagging overflow warnings.
9. **Separate Background & Overlay Viewports**:
   - `BackgroundRenderer`: Renders layout frames and cropped product images with all text tags hidden.
   - `OverlayRenderer`: Renders a transparent inline SVG container placing only the exact text, badges, prices, and QR codes.

### D. Export & AI Handoff Decisions

10. **Prompt Construction Pipeline**: Programmatic prompts (`lib/export/promptBuilder.ts`) will compile Brand Keywords, Aspect Ratios (e.g. `--ar 11:17` for letter size in Midjourney), grid summaries, and negative tokens (`negative-prompt.txt`) to enforce text suppression during AI polish.
11. **Overlay Alignment and Legibility Matrix**: The Final Compositor will allow manual translation scaling (X/Y global and section offsets) to compensate for minor AI layout shifts. A real-time contrast analyzer based on relative luminance will flag low contrast (ratio < 4.5:1 / 3:1) and suggest legibility overlays (backing panels, text outlines, or dropshadows).
12. **Vector PDF Exporter**: Playwright will print the composite layout viewport directly to PDF, ensuring that the transparent text SVG layers remain vector-perfect, sharp, and searchable.

### E. QA & Production Readiness Decisions

13. **Vitest and Snapshots**: Unit tests will check CSV parsing, formatting, and text-fitting. Bounding box JSON lists and SVG trees will be snapshot-tested under Vitest to verify coordinate stability.
14. **Playwright Visual Regression**: Visual differences on canvas presets (Letter, Poster, Instagram) will be verified with a `0.1%` pixel tolerance threshold to ignore minor OS-specific subpixel differences.
15. **Backend Security Guards**: Upload endpoints will parse image files using MIME type magic-bytes inspection (`file-type`), sanitize file names, rename files to UUIDs to prevent directory traversal, and process uploads through `Sharp` to strip EXIF metadata.

## 2. Decisions Rejected or Deferred

The following features and specifications are rejected or deferred to post-MVP iterations to preserve development focus and rapid execution:

| Feature / Decision                   | Status       | Rationale                                                                                                                                                                                        |
| :----------------------------------- | :----------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **In-App Image Generator APIs**      | **Deferred** | Simplifies scope. Focuses MVP on establishing a robust, manual copy-paste handoff ZIP package containing prompt markdowns.                                                                       |
| **Freeform Canvas Layering**         | **Rejected** | Avoids the complexity of Canva-cloning. Position coordinates must remain deterministic and computed by the layout solver.                                                                        |
| **Multi-page Catalogs**              | **Deferred** | Restricted to single-page canvas layouts (flyers, posters, social posts) for simplicity.                                                                                                         |
| **In-App Vector Background Removal** | **Deferred** | Simple rectangular cropping and focal-point centering are sufficient for the MVP.                                                                                                                |
| **Prisma Strict Relational Tables**  | **Rejected** | Relational mapping of layout parameters would slow schema modifications during layout solver iterations. Storing serialized `contentJson` in SQLite is faster and cleaner for early development. |

## 3. MVP Scope Changes

Three new entities and configuration schemas are added to the MVP scope to satisfy data integrity and export stability:

1. **`Asset` Entity**: To track MIME types, resolution, original file sizes, and responsive cropping parameters (specifically normalized focal points: `{ x: 0.5, y: 0.5 }`).
2. **`Template` Entity**: To separate built-in layout presets from user-created templates.
3. **`ExportPackageManifest` Entity**: A schema describing the structure, timestamp, files (`README.md`, `prompt.md`, renders, etc.), and original layout element boundaries inside the exported ZIP package.
4. **Layout Scoring Constraints**: Adding a layout validator that blocks export or falls back to standard listing forms if cards scale below `120px x 60px` or if overcrowding causes severe layout degradation.

## 5. Updated Acceptance Criteria

A project milestone is marked complete only if the output satisfies the following acceptance criteria:

1. **Schema & Version Stability**:
   - The application parses and validates project files using Zod, defaulting missing fields.
   - The migration pipeline updates legacy schema structures sequentially to the current version.
2. **Layout Engine Determinism**:
   - The HGP solver calculates and outputs absolute, non-overlapping `(x, y, w, h)` coordinates.
   - Modifying item priority dynamically reflows all other blocks without coordinate collisions.
3. **Text Formatting & Safety**:
   - Text overflows are resolved by scaling down (to a limit of 10px) and truncating with ellipses.
   - Font sizes below 10px and low-contrast conditions trigger visible editor warnings.
4. **Handoff Package Integrity**:
   - Clicking export generates a ZIP containing structured JSON files, cropped asset files, README instructions, custom prompt markdowns, text-suppressing negative prompts, text-free `rough-layout-background-only.png`, and transparent overlays.
5. **Fidelity Composite Quality**:
   - Uploading a background image and placing text overlays produces a print-resolution final image (300 DPI) and a PDF.
   - Text overlay elements inside the exported PDF remain vector-sharp, scalable, and searchable.

## 6. Open Questions

Before proceeding, the following design decisions require final clarification:

1. **Google Fonts Cache on Exporter**: Should we package Google Fonts (`WOFF2`) locally in the codebase public folder to prevent Playwright network requests and ensure font metrics match exactly on CI platforms?
2. **Focal Point Selector UI**: Should the focal point selector be built as a full interactive image modal, or can it be a simplified click-to-center cursor directly on the uploaded thumbnail image inside the Right Properties sidebar?
3. **Print safe bleed areas**: Do we need to visually represent standard print bleeds (e.g. 0.125 inch bleed bounds) on the canvas layout, or is it sufficient to let the `safeMarginPx` parameter handle this?
